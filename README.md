# 情侣报备审批微信小程序

> 一款情侣间专用的「出行报备 + 日常记账」小程序：双方绑定后可互相发起报备、审批、查看历史记录，还能共用一本情侣账本随手记账。

---

## 功能概览

| Tab | 页面 | 核心功能 |
|-----|------|---------|
| 报备 | 首页 | 发起报备（地点、同行人、归来时间、事由、图片凭证），顶部有「日常记账」入口卡片，提交时自动申请审批结果通知 |
| 消息 | 消息页 | 待我审批的报备 + 我收到的审批结果，可开启「新报备」订阅通知 |
| 记录 | 记录页 | 按时间倒序展示全部报备，支持按状态筛选 |
| 我的 | 个人中心 | 头像/昵称、绑定状态、邀请码、解绑/重新绑定 |

附加页面：
- **绑定页**：输入邀请码 / 扫码绑定伴侣
- **详情页**：查看报备全部信息 + 批准/驳回操作
- **记账页**：情侣共享账本（本月收支统计、分类占比、按月翻页、长按删除自己的账）
- **记一笔页**：支出/收入切换、分类图标、金额、备注、日期

## 数据库集合（云开发 → 数据库 → 创建）

总共 **4 个集合**：

### 1. `users` —— 用户表
| 字段 | 类型 | 说明 |
|------|------|------|
| `openid` | String | 微信用户唯一标识 |
| `nickName` | String | 昵称 |
| `avatarUrl` | String | 头像（云存储 fileID） |
| `bindCode` | String | 6 位邀请码 |
| `partnerId` | String | 绑定的伴侣用户 _id |
| `partnerName` | String | 伴侣昵称（冗余加速查询） |
| `bindTime` | Date | 绑定时间 |
| `createdAt` / `lastLoginAt` | Date | 注册时间 / 最近登录 |

### 2. `reports` —— 报备表
| 字段 | 类型 | 说明 |
|------|------|------|
| `openid` | String | 发起人 openid |
| `creatorId` | String | 发起人用户 _id |
| `creatorName` | String | 发起人昵称 |
| `partnerId` | String | 审批人（伴侣）用户 _id |
| `location` / `companions` / `returnTime` / `reason` | String | 报备内容 |
| `images` | Array<String> | 图片凭证 fileID |
| `status` | String | `pending` / `approved` / `rejected` |
| `rejectReason` | String | 驳回理由 |
| `createdAt` / `processedAt` | Date | 发起时间 / 处理时间 |
| `processedByName` | String | 处理人昵称 |

### 3. `subscriptions` —— 订阅消息额度表（一次性订阅）
| 字段 | 类型 | 说明 |
|------|------|------|
| `openid` | String | 授权用户 openid |
| `tmplId` | String | 模板 ID（区分是哪种通知） |
| `type` | String | `new_report`（报备提醒）/ `approve_result`（审批结果） |
| `count` | Number | 剩余可发送次数（用户授权一次 +1，发送一条 -1） |
| `createdAt` / `updatedAt` | Date | 创建 / 更新时间 |

> 一次性订阅消息机制：用户每点一次「允许」只产生 **1 条**发送额度，发完即止，需再次授权。

### 4. `bills` —— 账单表（情侣共享账本）
| 字段 | 类型 | 说明 |
|------|------|------|
| `openid` | String | 记账人 openid |
| `creatorId` | String | 记账人用户 _id（删除权限依据：只能删自己记的账） |
| `creatorName` | String | 记账人昵称 |
| `partnerId` | String | 对方用户 _id（冗余，双方查询共享账本用） |
| `type` | String | `expense`（支出）/ `income`（收入） |
| `category` | String | 分类 key（food/transport/shopping/fun/house/medical/gift/other/salary/sidejob/redpacket/invest） |
| `categoryName` | String | 分类中文名（冗余展示） |
| `amount` | Number | 金额（元，保留两位小数） |
| `note` | String | 备注（≤50 字） |
| `billDate` | String | 账单归属日期 `YYYY-MM-DD`（按月查询/分组用） |
| `createdAt` | Date | 记账时间 |

## 快速开始

### 第一步：导入项目

1. 打开 **微信开发者工具**
2. 点击「导入项目」→ 选择本文件夹 `小程序/`
3. AppID 自动填入 `wx0e1b01f2a3e33d55`，选「小程序」→ 确定

### 第二步：开通云开发

1. 开发者工具顶部点击「云开发」按钮（⚡图标）
2. 如果没有环境，点击「创建环境」，环境名称任意（如 `couple-report`）
3. 创建成功后，复制环境 ID（类似 `couple-report-xxxxx`）
4. 打开 `app.js`，把第 14 行的 `env: undefined` 改为：
   ```js
   env: 'couple-report-xxxxx',  // ← 改成你的环境ID
   ```
   （或保持 `undefined` 使用默认环境也可以）

### 第三步：创建数据库集合

1. 进入「云开发控制台」→「数据库」
2. 分别创建四个集合：`users`、`reports`、`subscriptions`、`bills`
3. **设置权限**（重要！）：
   - 点击 `users` 集合 →「权限设置」→「自定义安全规则」→ 粘贴：
     ```json
     {
       "read": false,
       "write": false
     }
     ```
   - 点击 `reports`、`subscriptions`、`bills` 集合 → 同样设置 `read: false, write: false`
   
   > 原因：所有数据读写都走云函数（云函数有管理员权限），前端不直接操作数据库，更安全。

### 第四步：配置订阅消息模板（重要！）

订阅消息需要先在微信公众平台申请模板，再填到代码里，否则收不到推送：

1. 登录 [微信公众平台](https://mp.weixin.qq.com)（小程序账号）
2. 左侧菜单「功能」→「订阅消息」→「公共模板库」
3. 搜索并选用合适的模板（个人主体小程序用「一次性订阅消息」）：
   - **报备提醒**（给审批方）：选择含「报备内容 / 报备时间 / 发起人」等关键词的模板，如「新订单提醒」类可改选「日程提醒」
   - **审批结果通知**（给发起方）：选择含「审批结果 / 报备内容 / 处理时间」等关键词的模板
   - *如果公共模板库没有完全匹配的，选关键词类型相近的即可（thing / time / name 均可）*
4. 添加后进入「我的模板」，复制每个模板的 **模板 ID**
5. 打开 `utils/config.js`，替换两个模板 ID 占位符
6. 打开 `cloudfunctions/sendNotify/index.js`，替换 `TEMPLATES` 里的两个模板 ID（**两处必须一致**）
7. 根据你实际申请的模板，检查 `createReport` / `approveReport` 云函数里的 `data` 字段编号（`thing1`/`time2`/`name3`）是否与模板关键词顺序一致，不一致就调整编号

> 💡 模板关键词类型对照：`thing` = 短文本（20字内）、`time` = 时间、`name` = 名字、`phrase` = 短语

### 第五步：部署云函数

1. 在微信开发者工具中，右键 `cloudfunctions/login` →「创建并部署：云端安装依赖」
2. 依次右键部署以下云函数（顺序无关）：
   - `bind`
   - `unbind`
   - `updateProfile`
   - `createReport`
   - `approveReport`
   - `getReports`
   - `getReportDetail`
   - `getMessages`
   - `subscribe`
   - `sendNotify`
   - `addBill`
   - `getBills`
   - `deleteBill`
   - `getBillStats`

3. 每个函数部署时等待「上传成功」提示即可

### 第六步：清空缓存重编译

1. 开发者工具菜单 →「工具」→「清除缓存」→「全部清除」
2. 重新编译（Ctrl + R）
3. 控制台应看到正常调用 `login` 云函数的输出

## 订阅消息通知是怎么工作的？

微信规定：小程序**不能主动**给用户发消息，必须由用户主动授权，且**授权一次只产生一条消息额度**。本项目的设计：

| 场景 | 谁授权 | 什么时候弹授权 | 发什么消息 |
|------|--------|--------------|-----------|
| 发起报备 | 发起方 | 点「发起报备」按钮时 | 审批结果通知（批准/驳回） |
| 收到报备 | 审批方 | 消息页顶部引导条点「开启」 | 报备提醒（TA 要去哪） |

**交互细节：**
- 首页每次提交报备前都会请求一次授权 → 对应这条报备的审批结果推送
- 消息页顶部有可关闭的引导条，开启后伴侣发报备会推送提醒
- 授权拒绝不阻塞主流程（报备照常提交，只是收不到推送）
- 一次性额度用完后需要再次授权，这是微信平台规则，无法绕过

**消息推送内容：**
- 报备提醒：`XX要去「地点」` + 预计归来时间（点击跳转消息页）
- 审批结果：`已批准 / 已驳回（附理由）`（点击跳转记录页）

## 体验完整流程（需要 2 个微信号）

> ⚠️ 微信开发者工具只能登录 1 个用户，实际体验需要 2 个微信账号（例如你和伴侣的手机号）。

### 方式 A：2 台真机
1. A 微信 → 打开小程序 → 进入「我的」→ 复制邀请码
2. B 微信 → 打开小程序 → 进入「我的」→「去绑定伴侣」→ 输入 A 的邀请码 → 绑定成功
3. A 发起报备 → B 收到消息 → B 在消息页点进去 → 批准/驳回
4. A 在「记录」和「消息」查看结果

### 方式 B：开发者工具 + 真机（1 人模拟）
1. 开发者工具模拟用户 A，真机微信（通过预览二维码或真机调试）登录用户 B
2. 按上述流程操作即可

## 常见问题

### Q1：为什么报错 `errCode: -501001`？
这是云函数未正确部署的提示。请回到第四步，确保所有云函数都已上传到云端。

### Q2：报错 `请使用 2.2.3 或以上的基础库`？
这是基础库版本太低。在开发者工具「详情」→「本地设置」里把「调试基础库」调到 `2.14.0` 或更高。

### Q3：绑定邀请码总是提示「无效」？
- 确认双方都已进入过小程序（触发 login 云函数创建了 users 记录）
- 邀请码区分大小写，直接复制最保险
- 双方必须都未绑定（已绑定的一方需先解绑）

### Q4：上传图片后无法预览？
- 确认已开通云存储：云开发控制台 →「存储」→「开通云存储」
- 确认云存储默认权限允许读写（默认「仅创建者可读写」即可，图片用 fileID 展示）

### Q5：订阅消息收不到推送？
- 确认 `utils/config.js` 和 `cloudfunctions/sendNotify/index.js` 里的模板 ID 都已替换成真实 ID（不是「请替换」占位符）
- 确认 `subscriptions` 集合已创建且权限为 `read:false, write:false`
- 确认 `subscribe`、`sendNotify` 两个云函数都已部署
- **版本限制**：`sendNotify` 里 `MINIPROGRAM_STATE = 'developer'` 只发给开发版/体验版用户；正式上线前必须改成 `'formal'`
- 一次性订阅额度用完就不会再发（用户需再次授权），这是微信平台规则
- 云开发环境需与小程序绑定（创建环境时默认已绑定，可在云开发控制台「设置」中确认）

### Q6：订阅消息模板关键词对不上怎么办？
- 每个模板的关键词编号（thing1、time2...）由公众平台分配，**以你在后台看到的为准**
- 在 `cloudfunctions/createReport` 和 `approveReport` 里调整 `data` 中的编号与值类型即可
- 值类型必须匹配：`thing` 传文本、`time` 传 `YYYY-MM-DD HH:mm`、`name` 传姓名
